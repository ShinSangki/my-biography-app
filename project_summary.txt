# My Biography App (음성 자서전 앱) 프로젝트 요약

이 문서는 다른 AI 에이전트에게 프로젝트의 구조와 역할을 설명하기 위해 작성된 전체 요약본입니다.

## 1. 프로젝트 개요
- 목적: 사용자가 자신의 이야기를 음성으로 녹음하면, AI가 이를 텍스트로 변환(STT)하고 자연스러운 문장으로 다듬어 자서전 형태로 만들어주는 서비스.
- 지원 플랫폼: 웹 프로그레시브 앱(Vercel 배포) 및 안드로이드 모바일 앱(Capacitor 기반 APK).

## 2. 프로젝트 폴더 구조
프로젝트는 크게 프론트엔드와 백엔드로 독립되어 구성됩니다.
- `d:\my-biography-app\frontend\`: React 기반 웹 프론트엔드 및 Capacitor를 이용한 안드로이드 앱 빌드 환경 (`android/` 폴더 포함).
- `d:\my-biography-app\backend\`: Express 기반 Node.js 백엔드 서버 (Render 플랫폼에 배포됨).

## 3. 기술 스택
- 프론트엔드: React, TypeScript, Capacitor (웹 기술로 모바일 앱 패키징)
- 백엔드: Node.js, Express, TypeScript, Multer (파일 업로드 처리)
- AI 연동: `@google/genai` (Google Gemini API를 이용한 오디오 파일 전사 및 자서전 텍스트 생성)

## 4. 주요 기능 및 파일 역할

### 프론트엔드 (`frontend/src/App.tsx`)
- MediaRecorder API를 사용하여 기기 마이크로 음성 녹음 (주로 `audio/webm` 형식).
- 녹음된 파일을 백엔드로 전송하고, STT 변환 -> 자서전 생성 -> 저장에 이르는 일련의 API 호출을 순차적으로 수행.
- 모바일 환경(APK)에서 서버를 정상적으로 찾을 수 있도록 백엔드 주소(`https://biography-backend.onrender.com`)가 코드에 하드코딩 되어있음.
- 자서전 목록 조회, 상세 보기, 내용 수정 및 삭제 기능 제공.

### 백엔드 API 흐름 (`frontend/API관련 정리.md` 참조)
1. `POST /upload`: 프론트엔드에서 전송한 오디오 파일을 서버 로컬(`backend/uploads/`)에 임시 저장.
2. `POST /recordings/save`: 업로드된 파일 경로와 메타데이터를 저장.
3. `POST /stt`: 오디오 파일을 Gemini API로 전송하여 텍스트로 변환(Speech-to-Text).
4. `POST /generate`: STT로 변환된 텍스트 원본을 바탕으로 프롬프트를 조합해 Gemini API를 호출하여 자서전 초안 문장 생성.
5. `POST /memoirs/save` (또는 내부 저장 로직): 생성된 자서전 내용 저장.
6. `GET /autobiographies`, `PUT /autobiographies/:id`, `DELETE /autobiographies/:id` 등을 통한 데이터 관리.

### 백엔드 핵심 로직 (`backend/src/services/geminiSTTService.ts` 등)
- 프론트엔드에서 올라온 WebM 오디오 파일을 호환성을 위해 WAV로 변환 (`ffmpeg` 등 활용).
- Gemini의 File API (`sttAi.files.upload`)를 통해 오디오 파일을 Google 서버에 업로드.
- 파일 상태가 `ACTIVE`가 될 때까지 폴링(Polling) 대기 후, `sttAi.models.generateContent`를 호출하여 한국어 음성 전사 수행.
- 사용 완료된 임시 파일 및 변환된 오디오 파일은 처리가 끝난 후 즉시 삭제 처리.

## 5. 실행 및 서버 배포 상태
- 프론트엔드(웹): Vercel에 배포되어 웹사이트 형태로 접근 가능.
- 프론트엔드(앱): `npx cap sync android` 및 안드로이드 스튜디오를 통해 `app-debug.apk`로 추출되어 스마트폰에 설치 가능.
- 백엔드: Render 클라우드 플랫폼에 배포되어 작동 중 (`https://biography-backend.onrender.com`). CORS가 전면 허용되어 모바일 앱 및 웹의 요청을 모두 수신 가능.
